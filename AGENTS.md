# Правила проекта LShift

## Публикация версий

- Завершённое обновление приложения с новой версией включает публикацию GitHub Release. Одного коммита или push в `main` недостаточно.
- Публикация готовой проверенной версии входит в согласованный процесс завершения обновления; отдельное повторное подтверждение пользователя не требуется, если он явно не отложил публикацию.
- Перед выпуском синхронизировать версию CMake, ресурсов Windows и документации, обновить `CHANGELOG.md`, выполнить необходимые проверки и отправить исходники в GitHub.
- Создать тег `v<версия>` на соответствующем коммите и опубликовать обычный релиз с описанием изменений на русском языке.
- Основной файл релиза — самостоятельный Windows x64 `LShift.exe`, пригодный для запуска сразу после скачивания. ZIP не должен быть обязательным способом получения приложения.
- После загрузки проверить опубликованный релиз, версию и размер EXE; скачать файл в проектную `.cache` и сверить SHA256 с проверенной сборкой. Финальный релиз должен быть опубликован, а не оставлен черновиком.
- В итоговом ответе дать ссылку на релиз. При сбое публикации явно указать незавершённый этап; не называть один push готовым выпуском.
- Изменение только документации или правил проекта само по себе не требует новой версии приложения.
