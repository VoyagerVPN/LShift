# Основания реализации MVP

Проверено по официальным источникам 21–22 октября 2026, Europe/Moscow.

- C++20 выбран как стабильный режим MSVC `/std:c++20`. Текущая документация MSVC отдельно различает C++20, C++23 preview и экспериментальный latest; новизна стандарта сама по себе не даёт преимуществ этой небольшой Win32 утилите. Используются RAII, стандартные контейнеры и `std::jthread`, строгий режим `/permissive-`, предупреждения `/W4 /WX` и статический runtime. [MSVC language standard](https://learn.microsoft.com/en-us/cpp/build/reference/std-specify-language-standard-version), [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines).
- Наблюдение: Raw Input с `RIDEV_INPUTSINK | RIDEV_DEVNOTIFY` на скрытое собственное окно. Глобальных клавиатурных/мышиных hooks нет; регистрация принадлежит процессу LShift. [RegisterRawInputDevices](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices).
- Трей: стабильный GUID, `NIM_ADD` и затем `NIM_SETVERSION/NOTIFYICON_VERSION_4`. После `TaskbarCreated` иконка регистрируется заново. [Notification Area](https://learn.microsoft.com/en-us/windows/win32/shell/notification-area).
- Автозапуск: запись текущего пользователя HKCU Run с кавыченным абсолютным EXE и `--autostart`, управляется только явным действием из UI. Запись Run и фактическое исполнение на следующем входе — отдельные проверки. [Run/RunOnce](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).
- UIA: COM MTA worker, отдельные таймауты соединения/транзакции и запрет автоматического изменения фокуса. Таймауты API не дают универсальной гарантии прерывания любого ошибочного провайдера. [Threading](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading), [IUIAutomation2](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nn-uiautomationclient-iuiautomation2).
- TextPattern подтверждает выделение и границу строки. Универсальной команды записи диапазона в нём нет. В 0.1.1 прежний путь `Select + Unicode SendInput` заменён системными командами выделения/копирования/одной вставки: реальный текст получается из буфера обмена, без доверия устаревшему UIA снимку после изменения DOM. Стандартные native edit сообщения сохранены. [TextPattern](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-about-text-and-textrange-patterns), [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput).
- Решение 0.1.1 о создании выделения для слова **заменено в 0.1.2** по результату пользовательской проверки. Короткий журнал физических VK/Shift/Caps хранится только в памяти; символы восстанавливаются через `ToUnicodeEx` с флагом 4 только на worker после жеста. Для слова обязательны совпадение системного суффикса с журналом и наличие начала всего слова внутри журнала. Сначала адресно переключается и подтверждается целевая раскладка; затем удаление и обычные VK-нажатия со scan code отправляются одним `SendInput`, без искусственных задержек. `VkKeyScanExW` и проверка через `ToUnicodeEx` подбирают Shift с учётом текущего Caps Lock, включая его переключение после последней буквы. Caps Lock не переключается программой. Clipboard остаётся только для пользовательского выделения. [ToUnicodeEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-tounicodeex), [VkKeyScanExW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-vkkeyscanexw).
- Raw Input мыши используется только для сброса по кнопкам, движения не обрабатываются. Дополнительные события фокуса/foreground приходят через `SetWinEventHook(WINEVENT_OUTOFCONTEXT)`: DLL в целевой процесс не загружается, callback асинхронный. В 0.1.10 прежняя безусловная отмена по событию фокуса заменена проверкой фактического контекста: accessibility может повторно объявить тот же фокус при подключении клиента. Новый ввод отменяет поколение команды; native HWND, UIA-элемент, курсор и текст проверяются перед записью, в том числе после смены раскладки. Устаревшее уведомление foreground не стирает более новый набор. Это архитектурные свойства; игровой frame time ими не измерен. [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook).
- Пользователь разрешил изменение буфера обмена, поскольку использует историю Windows. Автоматическое восстановление старого clipboard исключено из рабочего пути: оно могло подменить содержимое ещё не обработанной асинхронной вставки. Новый текст публикуется целиком, с exclusion-маркерами истории/облака. [Clipboard formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats).
- Меню трея открывается отдельным сообщением после Shell callback. Нулевой служебный HWND временно становится видимым foreground/topmost owner; после меню состояние восстанавливается. [TrackPopupMenuEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-trackpopupmenuex).

## Публичные границы проверок

В 0.1.11 удалён допуск UIA-элемента по фиксированным ролям Edit/Document. Поисковое поле с автодополнением может быть ComboBox и при этом предоставлять редактируемый TextPattern. Официальная документация различает роль контрола и поддерживаемые им patterns; пользовательские варианты контролов могут предоставлять дополнительные patterns. Поэтому проверяются процесс, доступность, отсутствие пароля и актуальный фокус, затем наличие TextPattern, диапазона и его IsReadOnly. Системное имя сайта/процесса не участвует в выборе пути. [Control types and supported patterns](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-controlpatternmapping).

В 0.1.10 журнал содержит скользящий кандидат последних 128 клавиш. Неизвестное начало после удаления или переполнения больше не запрещает записывать последующие клавиши: разрешение на удаление определяется полным совпадением фактического слова и хвоста до курсора с кандидатом. Слово, не помещающееся целиком, отвергается. Цифровой блок участвует в том же правиле; отдельное нажатие модификатора и команда без редактирования не уничтожают кандидат. UIA и декодирование символов остаются исключительно на worker по жесту. Отдельный интеграционный прогон проходит через реальный SendInput, Raw Input, распознаватель и worker запущенного приложения; прежний `ProcessText`-прогон проверяет редакторы и защитные условия независимо.

В 0.1.9 единый `KeyboardChordKey` определяет клавиши, участвующие в удерживаемом клавиатурном сочетании: ввод и редактирование, навигация, модификаторы, функциональные и OEM-клавиши. Классификация следует [таблице Virtual-Key Codes Windows](https://learn.microsoft.com/en-us/windows/win32/inputdev/virtual-key-codes). Команды мультимедиа, браузера, запуска приложений и сна, gamepad и резервные коды не сохраняются как удерживаемые клавиши. Это общее правило используется при начальном опросе Windows, в `Gesture::Feed`/`SetHeld` и финальной проверке перед отправкой задания. Команда между двумя нажатиями отменяет незавершённый жест, но не блокирует следующие. Внешних запросов на каждый обычный ввод не добавлено. Проверяется существующая публичная граница `Gesture`: сначала воспроизведение отказа, затем исправление и проверки классов команд, клавиш и устройств.

При дальнейших отказах сначала фиксируется состояние работающего экземпляра, до перезапуска. Исправляется подтверждённое правило и все места его применения; таблицы исключений для отдельных приложений, игр, производителей или одного обнаруженного VK не используются. Для изменения сохраняются воспроизводящий сценарий и проверка прежних защитных условий. Потенциальный риск и наблюдаемый отказ у пользователя отмечаются отдельно.

В 0.1.7 по принятому пользователем завершению функционального этапа стандартная сборка исключает `DiagnosticQueue`, обработку диагностических событий, файловый лог и пункт открытия журнала через `LSHIFT_DIAGNOSTICS=OFF`. Диагностический объектный модуль не связан с обычным EXE; его исходники и независимые тесты оставлены для разработки. Убраны копии журнала клавиш, ранее нужные только для решения о диагностической записи. Отдельная диагностическая сборка включается явно и имеет другой output-каталог. COM MTA инициализируется на уже ожидающем worker только при первой текстовой команде и закрывается на этом же потоке. Новый startup-контракт проверяется существующим пассивным `--smoke-test`: RED на 0.1.6, GREEN на 0.1.7; жесты и фокус пользователя тестом не изменяются.

Release-компоновка включает `/GL` и `/LTCG`, удаление неиспользуемых COMDAT и объединение одинаковых функций `/OPT:REF,ICF`. Режим оптимизации вычислений `/O2` сохранён. Основания: [MSVC LTCG](https://learn.microsoft.com/en-us/cpp/build/reference/ltcg-link-time-code-generation), [MSVC OPT](https://learn.microsoft.com/en-us/cpp/build/reference/opt-optimizations). Большие значки PNG и малые DIB объединены в один ICO/PE-ресурс; CMake отслеживает ICO как явную зависимость RC. [Windows icons](https://learn.microsoft.com/en-us/windows/win32/menurc/about-icons).

В 0.1.6 пользователь подтвердил правило ручного преобразования выделения по словам: однородные RU/US слова инвертируются независимо, смешанное внутри слово сохраняется целиком. `ConvertWords` — общий чистый преобразователь для native-выделения и UIA clipboard-пути; он возвращает целый фрагмент и направление последнего преобразованного слова для выбора HKL. Обе ветки по-прежнему заменяют выделение одной операцией. Проверка недавно набранного слова остаётся прежней: она требует одного алфавита и совпадения с журналом. Набор символов слова общий с `LastWord`: буквы RU/US, цифры, `_` и физические знаки буквенных клавиш (включая `;`). Прочие символы разделяют слова и сохраняются. Токены без букв не преобразуются; словари и адаптеры приложений не добавлены. Прежний отказ преобразовывать любое выделение с двумя алфавитами заменён этим правилом; отказ для одного смешанного слова сохранён.

В 0.1.4 наблюдение реального UIA-провайдера выявило выход Character-перемещения за пределы редактируемого поля. `text_context` теперь строит префикс и суффикс из `DocumentRange` поля через `MoveEndpointByRange`, без изменения выделения. После `GetSelection` границы поля получаются заново. Логический EOF может структурно сравниваться после конца DocumentRange, хотя фактические строки совпадают: такой случай допускается только при точном равенстве всего префикса всему тексту поля. Другой текст за полем отклоняется. Максимум чтения префикса — 64 Ki UTF-16 единиц; сохраняются последние 4096. [MoveEndpointByRange](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextrange-moveendpointbyrange).

В 0.1.5 Ctrl+A задаёт ожидание замены всего выделения. Backspace/Delete после него устанавливают новую границу истории, повторное удаление пустого поля её не теряет; прямой набор поверх выделения тоже начинает новый журнал. Мышь, смена контекста, навигация и посторонние hotkey отменяют ожидание. Это кандидат на новое слово, а не доказательство исполнения Ctrl+A редактором: перед отправкой удаления всё равно нужны полное совпадение изменяемого текста с физическими клавишами и начало целого слова внутри журнала. Отказ самого редактора обработать Ctrl+A отдельно покрыт интеграционной проверкой.

В 0.1.3 исправлена проверка после смены раскладки. В 0.1.2 весь журнал декодировался под новой HKL, хотя преобразовывалось только последнее слово. Набор `hello ghbdtn  ` успешно превращался в `hello привет  `, затем ошибочно отвергался, поскольку `hello` декодировалось как `руддщ`. Теперь сравнивается весь удаляемый фрагмент от начала последнего слова до курсора; журнал обязан содержать его целиком. Системные проверки фокуса, точного текста этого фрагмента и отсутствия выделения сохранены. RED подтверждён вторым переключением через публичный `ProcessText`, GREEN — цепочкой из 12 переключений без подмены исходного журнала.

Диагностика 0.1.3 фиксирует служебные события и фиксированные причины `TextResult`, без пользовательского текста и VK букв. Однопроизводительная/однопотребительская очередь ограничена 127 записями; producer UI-потока не ждёт worker и не пишет файлы. Worker пишет UTF-8 JSONL, ротирует два файла по 512 KiB. Диагностические ошибки не прерывают текстовую команду, переполнение очереди считается отдельно. События обычных букв в файл не отправляются.

Согласованные пользовательские сценарии задают границы TDD: автомат двойного физического левого Shift, преобразование RU/US с регистром, выбор последнего слова, сохранение выбранных настроек. Тесты наблюдают публичные API и фиксированные ожидаемые строки. RED выполнялся для этих основных срезов; для сохранения настроек использовался отдельный начальный stub, не попавший в приложение. Дополнительные проверки реестра, повреждённого INI и GUI добавлены как регрессии. Интеграционные проверки текстовых адаптеров выполнены после реализации; отсутствие проверки реального клиента не подменяется unit-тестом.

Браузерный тест независимо наблюдает фактический DOM, курсор, события ввода, выделение и промежуточные кадры. Отсутствие созданного программой выделения — обязательная проверка исправления слова. Нулевое число промежуточных кадров было добавлено как более строгий диагностический критерий и отдельно отражено в отчёте; быстрый пакет удаления/ввода не обещает атомарную перерисовку редактора. Успех функциональных проверок не означает успех этого дополнительного критерия.

## Ответственности

Обязательное ограничение пользователя: никаких адаптеров под отдельные приложения, проверок имён процессов, белых списков редакторов или чёрных списков игр. Выбор пути определяется только системными возможностями активного текстового поля. Названия приложений в исследовании и приёмке обозначают тестовые поверхности и не участвуют в поведении программы.

- `core`: чистые правила жеста и символов, без Win32 и чтения текста.
- `recent_input`: журнал максимум 128 физических клавиш, Shift/Caps/Backspace, сброс и защита от усечённого слова; без Win32 и динамической памяти.
- `main`: цикл сообщений, Raw Input, отмена устаревших команд, одна очередь и COM worker.
- `shell`: иконка/меню/настройки/пользовательская запись автозапуска.
- `text_service`: разрешение по реальным возможностям поля, проверка диапазона, замена и подтверждение раскладки.
- `text_context`: чтение только внутри UIA-диапазона подтверждённого поля, проверка EOF и ошибок провайдера.
- `clipboard`: ограниченная публикация Unicode и чтение результата копирования с проверкой sequence/процесса-владельца; без фонового мониторинга буфера.
- `diagnostics`: ограниченная очередь служебных событий и ротация журнала на worker.

Исходники исследованных сторонних приложений в реализацию не переносились. Исследовательские загрузки и tool-артефакты остаются в исключённой `.cache`.
